# Platform Overview

## Purpose

ExternalApps exists to run **multiple avenues of business from one platform**. Instead of
each venture reinventing its own structure, processes, and tooling, the platform provides
a shared operating framework and each venture applies it.

The platform's job is to make ventures:

- **Organized** — a consistent structure so any venture is legible to anyone on the team.
- **Developable** — a clear path from idea to operating business.
- **Sustainable** — financially durable, environmentally responsible, resilient.
- **Staffed well** — a workforce model that puts people where people add the most value.
- **Automated well** — machines carrying the repetitive load so people don't have to.

## What lives at the platform level vs. the venture level

| Concern | Platform level (`docs/`) | Venture level (`ventures/<name>/`) |
|---|---|---|
| Business structure | The standard model and options | The structure this venture actually uses |
| Development | Stage definitions and practices | This venture's roadmap and current stage |
| Sustainability | Principles and minimum standards | This venture's plan and metrics |
| Workforce | Hiring, roles, and growth framework | This venture's team and role map |
| Automation | Approved tools and patterns | What this venture has automated and how |

The platform level sets the defaults; a venture may deviate where it has a documented
reason. Deviations are recorded in the venture's `operations.md`.

## Platform lifecycle for a venture

```
Idea → Charter → Build → Operate → (Scale | Sustain | Wind down)
```

- **Idea** — captured anywhere; promoted when someone commits to championing it.
- **Charter** — the venture gets a directory, a charter, and an owner.
- **Build** — development toward first revenue / first users.
- **Operate** — running business; pillars reviewed on a regular cadence.
- **Scale / Sustain / Wind down** — the three honest end-states. Sustaining at a
  healthy steady state is a success, not a failure to scale. Winding down cleanly
  is documented so the platform keeps the learning.

## Reviews

Each active venture reviews its five pillars on a quarterly cadence and records the
outcome in its `roadmap.md`. The platform framework itself (`docs/`) is reviewed
yearly, or whenever a venture's documented deviation suggests the default is wrong.
